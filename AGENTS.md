# Agent notes

## Commands

- `bun install`, `bun run typecheck`, `bun run lint` (zero warnings), `bun run test`, `bun run check:repository`
- Kotlin unit tests, from `android/` after `bunx expo prebuild --platform android --no-install`:
  `JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home ANDROID_HOME=$HOME/Library/Android/sdk ./gradlew :multicam-capture:testDebugUnitTest :tip-jar:testDebugUnitTest`
- Debug APK for one emulator ABI: `./gradlew app:assembleDebug -PreactNativeArchitectures=arm64-v8a`
- Sideload release APK: `./gradlew app:assembleRelease -PreactNativeArchitectures=arm64-v8a,armeabi-v7a` (signed with the debug keystore)
- `android/` and `ios/` are generated by prebuild and gitignored. After Expo patch bumps, a stale `ios/Podfile.lock` fails `pod install`; `cd ios && pod update --no-repo-update` fixes it.

## Shared contracts

- `tests/library/fixtures/android-recovery.json` is checked by both `RecoveryContractTest.kt` and `tests/library/recovery-contract.test.ts`. Change the Kotlin recovery rules and the fixture together.
- `Icon` only accepts names in `src/components/icon-sources.ts`, so a new SF Symbol needs an Android glyph there.
- `plugins/with-fresh-launch-screen` must stay before `expo-splash-screen` in `app.json`. It gives the iOS launch assets content-hashed names, because iOS caches launch art by name across app updates.

## Emulator e2e

- Use your own emulator port and Metro port, and `adb reverse tcp:<port> tcp:<port>`. Launch the dev client with
  `adb shell am start -a android.intent.action.VIEW -d "exp+open-multicam://expo-development-client/?url=http%3A%2F%2F127.0.0.1%3A<port>"`.
- Metro's file watcher can miss edits made after it started. If a JS change does not show up on the device, restart Metro with `--clear`.
- RN 0.86 does not forward `console.log` to Metro or logcat; surface debug values through UI text or accessibility labels instead.
- The emulator exposes one 1080p camera (front), no concurrent pairs, so two-camera modes cannot run there.
- `-gpu swiftshader_indirect` aborted the emulator under camera load; the default GPU works.
- Thermal states: `adb shell cmd thermalservice override-status 4` (critical), `0` to reset.
- uiautomator cannot dump while the recording timer or the video player animates; use screenshots then.

## Cloud simulator (Expo Simulators)

`bun run ios:cloud` runs this app on an Expo Simulators cloud device in the same way as `bun run ios`:

- It makes the same Debug build. While the native fingerprint does not change, it reuses the build.
- It runs Metro on its own port (never 8081) behind Expo's tunnel and connects the dev client, so Fast Refresh works.
- It opens the browser preview.

Ctrl+C stops Metro and the cloud device.

Agents:

1. Run `bun run ios:cloud -- --detach`.
2. Drive the device with `cloudsim exec bunx agent-device@latest snapshot -i` and `press @eN`. Take screenshots with `cloudsim shot <png>`.
3. Always finish with `cloudsim stop`. Sessions are billed.

`cloudsim doctor` checks the setup. See `~/Documents/code/cloudsim/README.md` and the `eas-simulator` skill.

## Over-the-air updates (EAS Update)

Updates are on only for TestFlight builds (`internal-ota`, channel `internal`, internal and external groups), their ad hoc copy for registered devices (`internal-ota-device`, also channel `internal`), and the simulator check build (`verify-simulator`, channel `verify`). The App Store build keeps them off, because the privacy policy names the Expo Observe reports as the only data the app sends. Before you publish or change anything about updates, read `docs/internal-updates.md`. It describes the verify-then-ship workflows and the separate internal version line.

## Expo Observe

Release builds send anonymous crash, error and performance reports to Expo Observe. `docs/privacy.md` and the store answers in `docs/app-store.md` promise exactly that data, and `tests/capture/production-privacy.test.ts` enforces it.

- Setup lives in `src/app/_layout.tsx`: `<ObserveRoot>` with `FallbackScreen` (`src/screens/shell/fallback-screen.tsx`) as the whole-app error fallback, and the app's only `Observe.configure` call at module scope. Keep it the only call: a second call replaces the whole configuration. It turns on the Expo Router integration, filters `recordingSetId` out of route metrics, and tags simulator runs (PR evidence, Expo Simulators, `verify-simulator`) as environment `simulator`. A new dynamic route parameter must go into `filteredParams`; the privacy test fails otherwise.
- Time to interactive: `useObserve().markInteractive()` runs on the capture screen when the launch image lifts (`captureState` says whether the cameras, the permission screen or an error showed), and on the library, take detail, settings, support and privacy screens once their content replaced any spinner. Add it to every new screen.
- Handled errors go through `reportHandledError` and `reportCaptureFailure` in `src/core/telemetry/observe.ts`, never `Observe.reportError` directly. They name the failure site, report capture failures by code only, and remove URIs, paths and quoted names. Current sites: capture prepare, validate, configure, start and stop; library read; take load, rename, share, save and delete; donation status, purchase and restore.
- Do not add `networkTraces`, `logEvent`, `setGlobalAttributes`, a custom `endpointUrl` or `dispatchInDebug` without first updating the privacy policy and the store answers. Debug builds do not dispatch.
- Query: `eas observe:versions`, `eas observe:metrics-summary --environment production`, `eas observe:routes`, `eas observe:errors` (add `--fingerprint` for stack traces) and `eas observe:session`, or the Expo MCP `observe_*` tools (`observe_metrics_summary`, `observe_errors`, `observe_routes`, `observe_versions`, `observe_session`). Use `--environment production` to leave out simulator runs.
- Source maps: `production` and the profiles that extend it set `uploadSourceMaps`, and `.eas/workflows/verify-update.yml` publishes with `--upload-source-maps`. Any new `eas update` publish needs that flag; `tests/features/observe-build-config.test.ts` checks it.
- dSYM files: iOS builds from `production` and the profiles that extend it keep `ios/build/*.app.dSYM.zip` as a build artifact. For every build you release, download it from the build page and upload it in Observe > Errors > Upload debug symbols, or in Project settings > Observe debug symbols. Native crash frames then show function names.

## Simulator evidence in fix PRs

For a simulator-verified fix, follow [the PR media procedure](docs/pr-simulator-media.md) from the first reproduction. Include the before and after screenshots, animated previews and full recordings in the PR description.

For a simulator-verified PR, include the issue-specific scenario when opening the PR to trigger the recording job described in `docs/pr-simulator-media.md`. Set `camera: true` for capture-screen checks.
